# RF02 — Bloquear o acesso com credenciais inválidas e exibir mensagem de erro

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Acesso |
| **Atualizado em** | 21/10/2026 |

## Objetivo

Impedir acessos indevidos sem revelar se uma conta existe e dificultar tentativas
repetidas de adivinhar senhas.

## Descrição

Quando o usuário ou a senha não conferem, ou quando a conta está inativa, o sistema
nega o acesso. A mensagem é sempre a mesma e não indica qual dado está errado. Depois
de **5** tentativas seguidas sem sucesso para o mesmo login, novas tentativas ficam
bloqueadas por **15 minutos** (DEC-28). Toda tentativa negada vai
para o log de auditoria.

## Perfis envolvidos

Qualquer pessoa que tente entrar (funcionário ou pessoa sem conta).

## Pré-condições

A tela de login está acessível (RF01).

## Fluxo principal

1. O usuário envia usuário e senha.
2. O servidor confere se o login está bloqueado. Se estiver, vai para a exceção E2.
3. O servidor confere a credencial. Se ela não confere ou a conta está inativa:
   1. soma 1 ao contador de falhas **desse login**, exista a conta ou não;
   2. grava no log `LOGIN_FALHA`, com o login mascarado, data e hora e origem, **sem a
      senha**;
   3. volta para a tela de login com a mensagem genérica, o campo usuário preenchido e
      o campo senha vazio.
4. Se o contador chega a **5** (PEND-04, DEC-28), o login fica bloqueado durante
   **15 minutos**. O log registra
   `LOGIN_BLOQUEADO`.
5. Um login com sucesso (RF01) zera o contador.

## Exceções e mensagens

| ID | Situação | Mensagem |
|---|---|---|
| E1 | Usuário inexistente, senha errada ou conta inativa | "Usuário ou senha inválidos. Confira os dados e tente novamente." |
| E2 | Login bloqueado por excesso de tentativas | "Muitas tentativas sem sucesso. Aguarde alguns minutos e tente novamente." [PROP: texto]. Aparece **igual** para contas existentes e inexistentes |
| E3 | Campo usuário ou senha vazio | "Informe o usuário." / "Informe a senha." Validação de preenchimento, sem consultar a conta |

As mensagens aparecem em uma região com `role="alert"`. O foco vai para o primeiro
campo com erro. O erro não substitui o indicador de foco (A11 §5.9.9, §5.1.1).

## Dados utilizados

| Dado | Uso |
|---|---|
| Login informado, normalizado | Chave do contador de falhas |
| Contador de falhas e horário do bloqueio | Guardados no servidor. Como guardar fica a cargo da implementação [PROP: em memória no protótipo, que só tem uma instância] |
| `usuario.ativo` | Conta inativa conta como falha |
| Log de auditoria | `LOGIN_FALHA`, `LOGIN_BLOQUEADO`, com login mascarado (por exemplo `c***@example.com`) |

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF02-01 | Senha errada para um login existente e qualquer senha para um login inexistente produzem **a mesma** mensagem, o mesmo código HTTP e a mesma tela |
| CA-RF02-02 | Uma conta inativa com a senha correta recebe a mesma mensagem do CA-RF02-01 |
| CA-RF02-03 | Depois de 5 falhas seguidas, a sexta tentativa, **mesmo com a senha correta**, é recusada com a mensagem E2 enquanto durar o bloqueio |
| CA-RF02-04 | Passado o tempo de bloqueio, a senha correta volta a autenticar |
| CA-RF02-05 | Um login com sucesso zera o contador de falhas |
| CA-RF02-06 | Cada falha gera uma entrada `LOGIN_FALHA` no log, sem a senha digitada |
| CA-RF02-07 | Depois do erro, o campo usuário continua preenchido, o campo senha fica vazio e a mensagem é anunciada por leitor de tela |
| CA-RF02-08 | O bloqueio funciona igual para logins inexistentes, sem revelar a existência da conta pelo comportamento |
