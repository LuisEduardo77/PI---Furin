# RF26 — Gerenciar contas da equipe *(novo)*

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Contas |
| **Atualizado em** | 21/10/2026 |

> **Título reescrito, mesmo ID (DEC-39).** Antes: "Gerenciar contas do perfil Gestão".
> Com o perfil único `FUNCIONARIO` (DEC-37), qualquer funcionário gerencia as contas da
> equipe.

## Objetivo

Permitir que a própria equipe da escola (ATE e Gestão Escolar) crie e desative as
contas de quem usa o sistema, cada uma individual, sem depender de script.

## Descrição

Qualquer usuário `FUNCIONARIO` pode:

- **criar** contas `FUNCIONARIO`;
- **gerar nova senha temporária** para elas;
- **desativar** e **reativar** essas contas.

A senha inicial é aleatória, aparece uma única vez, vale por 72 h e exige troca no
primeiro acesso (RN14). As primeiras contas vêm da carga inicial. **Ninguém desativa a
própria conta**, para o sistema nunca ficar sem nenhum acesso por engano.

Só existem contas da equipe. Alunos e pais/responsáveis **não têm conta** (DEC-37).

## Perfis envolvidos

**FUNCIONARIO.**

## Pré-condições

- O funcionário está autenticado.
- As primeiras contas vieram da carga inicial.

## Fluxo principal

### Listar

1. O funcionário abre **Contas da equipe** ("Contas da equipe | Furin Access").
2. A tela lista as contas com nome, login, situação (Ativa/Inativa) e data de criação.

### Criar

1. O funcionário aciona **"Nova conta"** e informa:
   - **Nome** (obrigatório);
   - **Login** (obrigatório e único), em texto livre, por exemplo `ate.nome` ou
     `secretaria.nome` (DEC-28, E6).
2. O servidor cria o `usuario` com `perfil = FUNCIONARIO` (fixo, nunca vindo da
   interface), `ativo = 1`, `troca_senha_obrigatoria = 1` e `senha_temporaria_expira_em`
   = agora + 72 h. A senha temporária tem **12 caracteres**, é gerada com `SecureRandom`
   e é gravada só como hash (RN14).
3. A senha aparece **uma única vez**, com `Cache-Control: no-store` (DEC-28, E7):
   > "Conta criada para Paula Exemplo. Senha temporária: `••••••••••••` [Mostrar]
   > [Copiar]. Entregue a senha à pessoa de forma reservada. Ela vale por 72 horas e
   > não será exibida novamente." [PROP: texto]
4. O evento `CONTA_CRIADA` vai para o log, com o autor e sem a senha.

### Gerar nova senha, desativar e reativar

1. Na lista, cada conta tem as ações:
   - "Gerar nova senha temporária para Paula Exemplo";
   - "Desativar Paula Exemplo" ou "Reativar Paula Exemplo".
2. Cada ação pede confirmação (A11 §5.9.12).
3. O efeito de cada ação:
   - **Nova senha:** igual à criação. A senha anterior deixa de valer.
   - **Desativar:** `ativo = 0`. O login é negado, e a autoria dos registros antigos é
     preservada (A10 §5.16).
   - **Reativar:** `ativo = 1`. Exige uma nova senha temporária [PROP: detalhe].
4. Os eventos `SENHA_TEMPORARIA_GERADA`, `CONTA_DESATIVADA` e `CONTA_REATIVADA` vão para
   o log.

## Exceções e mensagens

| Situação | Mensagem |
|---|---|
| Login já em uso | "Este login já está em uso. Escolha outro." [PROP: texto] |
| Nome ou login vazio | "Informe o nome." / "Informe o login." [PROP: texto] |
| Tentativa de desativar a própria conta | "Você não pode desativar a sua própria conta." [PROP: texto] |
| Requisição com outro valor de perfil | Ignorado. O perfil é sempre `FUNCIONARIO` |
| ID de conta inexistente | 404, e o evento vai para o log |
| Usuário não autenticado acessa `/contas/equipe/**` | Redireciona para o login |

Os erros seguem A11 §5.9.9: mensagem descritiva, `aria-invalid` e dados preservados.

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF26-01 | `gestao.demo` cria uma conta. A nova conta tem `perfil = FUNCIONARIO`, `troca_senha_obrigatoria = 1` e validade de 72 h, e no primeiro acesso cai na troca de senha (RF01) |
| CA-RF26-02 | A senha temporária tem 12 caracteres, aparece uma vez, fica só como hash no banco e não aparece no log |
| CA-RF26-03 | Uma requisição com outro valor de `perfil` cria a conta como `FUNCIONARIO` |
| CA-RF26-04 | `ate.demo` também consegue criar, desativar e reativar contas (DEC-39) |
| CA-RF26-05 | Nenhum funcionário consegue desativar a própria conta |
| CA-RF26-06 | Uma conta desativada não entra. Os registros antigos continuam mostrando o nome do autor (RF19) |
| CA-RF26-07 | Um usuário não autenticado que chama `/contas/equipe/**` é levado ao login. Um ID de conta inexistente retorna 404 |
| CA-RF26-08 | Cada ação pede confirmação. Os botões têm nomes acessíveis com o nome da pessoa e funcionam por teclado |
| CA-RF26-09 | Recarregar ou voltar para a página da senha não mostra a senha de novo. A resposta tem `Cache-Control: no-store` |
