# RF03 — Direcionar cada usuário às telas do seu perfil

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Acesso |
| **Atualizado em** | 21/10/2026 |

## Objetivo

Levar cada funcionário à tela inicial certa, com um menu sempre igual, e impedir no
servidor que alguém sem login ou com a conta inativa use qualquer função.

## Descrição

O sistema tem **um único perfil**, `FUNCIONARIO` (DEC-37). O ATE e a Gestão Escolar
são cargos diferentes, mas usam o sistema da mesma forma, com todas as funções. Alunos
e pais/responsáveis **não têm conta**.

Depois do login (RF01), o funcionário vai para a **Portaria** e vê o menu completo,
sempre na mesma ordem. Toda requisição é autorizada no servidor. Qualquer rota que não
esteja expressamente liberada para o perfil `FUNCIONARIO` é negada.

O campo `perfil` continua no banco, com um único valor, para que um perfil novo possa
ser criado no futuro sem mudar o modelo.

## Perfis envolvidos

**FUNCIONARIO.**

## Pré-condições

O usuário está autenticado e sem troca de senha pendente (RF01).

## Fluxo principal

1. Depois do login, o servidor confere o perfil `FUNCIONARIO`.
2. O servidor leva o usuário para a **Portaria** (`/portaria`), com o título
   "Portaria | Furin Access".
3. A tela mostra o menu, sempre nesta ordem:

   > Portaria · Alunos · Presentes · Histórico · Contas da equipe · Alterar senha · Sair

   A11 §5.7.15 define a ordem "Portaria, Alunos, Presentes e Histórico". Os demais
   itens são [PROP].
4. Em cada requisição, o servidor confere se o usuário está autenticado, se a conta
   está ativa e se a rota está liberada para o perfil `FUNCIONARIO`, conforme a matriz
   de [escopo-e-perfis.md §6](../../docs/escopo-e-perfis.md).

## Exceções e mensagens

| Situação | Resposta | Mensagem |
|---|---|---|
| Usuário não autenticado acessa uma rota restrita | Redireciona para o login | — |
| Conta desativada durante a sessão | A próxima requisição encerra a sessão e leva ao login | "Sua conta foi desativada. Procure a equipe da escola." [PROP: texto] |
| Rota existente que não foi liberada para o perfil (negar por padrão) | HTTP 403, com página acessível. O evento vai para o log | "Acesso não permitido." Link "Voltar ao início" [PROP: texto] |
| Rota inexistente | 404 | "Página não encontrada." |
| Requisição de alteração (POST) sem token CSRF | Recusada (A10 §8.28) | Página de erro genérica |

## Dados utilizados

| Dado | Uso |
|---|---|
| `usuario.perfil` | Sempre `FUNCIONARIO` (`ROLE_FUNCIONARIO`) |
| `usuario.ativo` | Conta inativa não acessa nada |
| Log de auditoria | `ACESSO_NEGADO`, com rota e usuário mascarado (A10 §8.15) |

## Regras de negócio relacionadas

Nenhuma RN específica. A matriz de permissões está em
[escopo-e-perfis §6](../../docs/escopo-e-perfis.md).

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF03-01 | Depois do login, `ate.demo` e `gestao.demo` caem em `/portaria` e veem o mesmo menu |
| CA-RF03-02 | O menu mostra os itens do fluxo, na ordem definida, em todas as telas |
| CA-RF03-03 | Um teste parametrizado de **todas as rotas × três situações** (sem login, `FUNCIONARIO` ativo e conta desativada) confirma: sem login vai para o login, `FUNCIONARIO` ativo acessa, conta desativada é encerrada |
| CA-RF03-04 | Uma rota nova sem regra de autorização explícita é negada (teste com uma rota de exemplo) |
| CA-RF03-05 | Toda negação vai para o log como `ACESSO_NEGADO`, sem dados pessoais completos |
| CA-RF03-06 | A página 403 tem título, h1, texto explicativo e um link de volta acessível por teclado |
| CA-RF03-07 | Todas as páginas têm o link "Ir para o conteúdo principal" como primeiro elemento focável (A11 §5.7.12) |
| CA-RF03-08 | Não existe nenhuma tela, rota ou menu para alunos ou pais/responsáveis (DEC-37) |
