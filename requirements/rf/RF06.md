# RF06 — Impedir cadastro com matrícula ou código de carteirinha duplicados

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Cadastro |
| **Atualizado em** | 21/10/2026 |

## Objetivo

Garantir que cada matrícula identifique um único aluno e que cada código de
carteirinha aponte para uma única credencial, para que a leitura na portaria nunca
fique ambígua.

## Descrição

O sistema impede três situações:

- cadastrar um aluno com uma matrícula que já existe;
- alterar uma matrícula para uma que já existe;
- emitir uma carteirinha com um código já usado, inclusive códigos de carteirinhas
  revogadas.

A verificação fica nos serviços (com a mensagem de duplicidade da tabela de exceções) e também nas restrições UNIQUE
do banco, que valem mesmo com requisições simultâneas.

## Perfis envolvidos

**FUNCIONARIO**, no cadastro (RF04), na edição (RF08) e na emissão de carteirinha (RF07).

## Pré-condições

O funcionário está no cadastro, na edição do aluno ou na emissão de carteirinha.

## Fluxo principal

### Matrícula

1. Ao salvar o cadastro ou a edição, o serviço normaliza a matrícula, tirando os
   espaços das pontas. Os zeros à esquerda são mantidos.
2. O serviço procura a matrícula entre **todos** os alunos, ativos e inativos. Na
   edição, o próprio aluno fica de fora da busca.
3. Se encontrar, recusa com a mensagem da tabela de exceções e mostra um link para o
   cadastro existente.
4. Se não encontrar, grava. Se duas gravações simultâneas passarem pela verificação, a
   restrição `uk_aluno_matricula` barra a segunda. O serviço traduz o erro do banco
   para a mesma mensagem de matrícula duplicada.

### Código da carteirinha

1. O código é **gerado pelo sistema** (RF07), nunca digitado.
2. Antes de gravar, o serviço confere se o código é único em **todas** as
   carteirinhas, inclusive as revogadas.
3. Se houver colisão, que é muito improvável com 128 bits aleatórios, o serviço gera
   outro código e tenta de novo. São até **3 novas tentativas**
   (DEC-28, D7). Se todas falharem, o cadastro é recusado com erro genérico.
4. A restrição `uk_carteirinha_codigo` garante a unicidade no banco.

## Exceções e mensagens

| Situação | Mensagem | Fonte |
|---|---|---|
| Matrícula já cadastrada para outro aluno, ativo ou inativo | "Esta matrícula já está cadastrada. Confira a matrícula ou localize o cadastro existente para editá-lo." Link "Abrir cadastro existente" | A11 p.4 §5.9.9, §5.9.10 |
| Colisão de código que persiste depois das novas tentativas | "Não foi possível emitir a carteirinha. Tente novamente." O evento vai para o log | [PROP] |

O campo Matrícula recebe `aria-invalid="true"` e `aria-describedby` apontando para a
mensagem. Os demais dados continuam preenchidos (A11 §5.9.9).

## Dados utilizados

| Dado | Restrição |
|---|---|
| `aluno.matricula` | `UNIQUE(matricula)`, VARCHAR(30), comparação na collation da tabela |
| `carteirinha.codigo` | `UNIQUE(codigo)`, CHAR(32) ASCII, comparação binária |

## Regras de negócio relacionadas

- **RN15:** carteirinha (códigos revogados nunca são reaproveitados).
- **RN16:** cadastro completo (a falha aqui desfaz o cadastro inteiro).

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF06-01 | Cadastrar um aluno com a matrícula "000123", já usada, é recusado com a mensagem de A11 e o link para o cadastro existente |
| CA-RF06-02 | A matrícula de um aluno **inativo** também bloqueia um novo cadastro (não há reutilização) |
| CA-RF06-03 | " 000123 " (com espaços) é tratada como "000123". "123" é **diferente** de "000123" (os zeros à esquerda contam) |
| CA-RF06-04 | Editar o aluno sem alterar a matrícula não acusa duplicidade com ele mesmo |
| CA-RF06-05 | Duas requisições simultâneas com a mesma matrícula nova resultam em um cadastro só. A outra recebe a mensagem de matrícula duplicada deste RF, e não um erro 500 |
| CA-RF06-06 | Um código de carteirinha igual ao de uma carteirinha revogada é recusado pelo banco (teste direto na restrição) |
| CA-RF06-07 | Uma colisão de código simulada no teste gera um novo código automaticamente, e o cadastro conclui |
| CA-RF06-08 | O campo Matrícula com erro tem `aria-invalid` e mensagem associada, e os outros campos continuam preenchidos |
