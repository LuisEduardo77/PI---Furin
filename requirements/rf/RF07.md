# RF07 — Gerar o QR Code do aluno para impressão da carteirinha

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Cadastro |
| **Atualizado em** | 21/10/2026 |

## Objetivo

Dar a cada aluno uma credencial física que um leitor de QR Code reconheça, sem
expor dados pessoais no código.

## Descrição

O sistema emite uma carteirinha para o aluno:

- gera um **código aleatório opaco** de 32 caracteres hexadecimais;
- codifica esse código em um **QR Code**;
- oferece uma página para imprimir a carteirinha.

Cada aluno tem no máximo uma carteirinha válida. Emitir uma **segunda via** gera um
código novo e revoga o anterior.

## Perfis envolvidos

**FUNCIONARIO.**

## Pré-condições

- O aluno está sendo cadastrado (RF04) ou já está cadastrado e ativo.
- Para uma segunda via: o aluno já tem uma carteirinha válida, ou a anterior foi
  perdida.

## Fluxo principal

### Emissão no cadastro

1. Na transação do RF04, o serviço gera 16 bytes com `SecureRandom` e os converte em
   32 caracteres hexadecimais minúsculos.
2. O serviço confere a unicidade (RF06) e grava a `carteirinha`:
   - `emitida_em` = agora;
   - `expira_em` = NULL (sem prazo no MVP, DEC-28, D9);
   - `revogada_em` = NULL.
3. Depois de salvar, o funcionário pode acionar **"Imprimir carteirinha"**.

### Impressão

1. A página "Carteirinha de Ana Teste | Furin Access" mostra o layout de impressão
   (DEC-28, D8), em formato de cartão de **85,6 × 54 mm**, sem foto e sem o código em texto:
   - nome do aluno;
   - turma;
   - QR Code com o código;
   - nome do sistema.
2. O QR Code é gerado no servidor (ZXing), como imagem PNG. O nível de correção de
   erro é **M** e o lado impresso tem pelo menos **2,5 cm** (DEC-28, D9).
3. O funcionário usa a impressão do navegador (`@media print`).

### Segunda via

1. Na página do aluno, o funcionário aciona **"Emitir segunda via"**.
2. O sistema pede confirmação: "A carteirinha atual deixará de funcionar. Confirmar?"
   (A11 §5.9.12).
3. Em uma transação, com o aluno bloqueado, o serviço:
   - preenche `revogada_em` = agora na carteirinha atual;
   - gera e grava uma nova carteirinha.
4. A partir daí, uma leitura da carteirinha antiga é recusada (RN09, RF23).
5. O evento `CARTEIRINHA_SEGUNDA_VIA` vai para o log.

## Exceções e mensagens

| Situação | Comportamento | Mensagem |
|---|---|---|
| Aluno inativo | Emissão recusada | "Não é possível emitir carteirinha para aluno inativo." [PROP] |
| Colisão de código | Nova tentativa automática (RF06) | — |
| Falha na geração da imagem do QR Code | O cadastro continua salvo. A impressão pode ser tentada de novo | "Não foi possível gerar o QR Code agora. Tente imprimir novamente." [PROP] |
| Leitura de carteirinha revogada | Recusada na portaria | Painel do funcionário: "Carteirinha revogada/expirada. Emitir segunda via" (RN09) |

## Dados utilizados

| Dado | Campo | Observação |
|---|---|---|
| Código | `carteirinha.codigo` | 32 caracteres hexadecimais, UNIQUE, sem dados pessoais |
| Emissão, expiração, revogação | `emitida_em`, `expira_em`, `revogada_em` | UTC |
| Nome e turma | `aluno.nome`, `vinculo_turma` vigente | Só na impressão |
| Conteúdo do QR Code | **Somente o código** | Nem nome, nem matrícula, nem URL (DEC-28, D8) |

## Regras de negócio relacionadas

- **RN15:** carteirinha (uma válida, segunda via revoga, sem reaproveitamento).
- **RN16:** emissão faz parte do cadastro completo.
- **RN09:** leitura de carteirinha revogada ou expirada.

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF07-01 | O código gerado tem exatamente 32 caracteres no intervalo `[0-9a-f]` e vem de `SecureRandom` (teste de unidade e revisão de código) |
| CA-RF07-02 | O QR Code impresso, lido por um decodificador em teste automatizado (no protótipo não há leitor USB, DEC-25), devolve exatamente o `codigo` |
| CA-RF07-03 | O conteúdo do QR Code não tem nome, matrícula, turma nem outro dado pessoal |
| CA-RF07-04 | Depois da segunda via, o aluno tem **uma** carteirinha válida, a anterior tem `revogada_em` preenchido, e a leitura da anterior é recusada |
| CA-RF07-05 | A segunda via pede confirmação antes de revogar (A11 §5.9.12) |
| CA-RF07-06 | Sem login, a emissão e a impressão levam à tela de login |
| CA-RF07-07 | A página de impressão tem título próprio. A imagem do QR Code tem `alt="QR Code da carteirinha de Ana Teste"`, sem o código no texto alternativo |
| CA-RF07-08 | Na implantação, leitores em modo teclado (RNF07) leem o QR Code impresso. **Não se aplica ao protótipo** (DEC-25) |
