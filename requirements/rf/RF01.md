# RF01 — Autenticar o usuário com usuário e senha individuais

| Campo | Valor |
|---|---|
| **Documentação** | Revisada em 21/10/2026 (DEC-37 a DEC-39) |
| **Implementação** | Planejada |
| **Grupo** | Acesso |
| **Atualizado em** | 21/10/2026 |

## Objetivo

Garantir que só pessoas autorizadas, cada uma com a própria conta, acessem as áreas
restritas, e que toda ação fique associada a quem a fez.

## Descrição

O sistema autentica por usuário (login) e senha individuais os funcionários, todos com o
perfil `FUNCIONARIO` (DEC-37). Alunos e pais/responsáveis não têm conta. Quem entra com uma **senha temporária** precisa definir uma nova senha
antes de usar qualquer outra função. O logout encerra a sessão. Uma sessão sem uso
expira depois de **30 minutos** de inatividade, com aviso acessível **60 s** antes (DEC-28).

## Perfis envolvidos

FUNCIONARIO.

## Pré-condições

- A conta existe: veio da carga inicial ou foi criada por outro funcionário (RF26).
- O usuário está usando um navegador compatível (RNF01).

## Fluxo principal

1. O usuário abre o sistema e vê a tela "Login | Furin Access".
2. Ele informa o usuário e a senha e aciona "Entrar".
3. O servidor normaliza o login (tira os espaços das pontas e passa para minúsculas).
   Depois confere se a conta existe e está ativa, se a senha confere com o hash e se o
   login não está bloqueado (RF02).
4. O servidor cria uma **nova sessão**.
5. O servidor confere a situação da senha:
   - se `troca_senha_obrigatoria = 1`, o usuário vai para "Definir nova senha" (fluxo
     alternativo A1);
   - caso contrário, vai para a tela inicial do perfil (RF03).
6. O evento "login com sucesso" vai para o log de auditoria (A10 §8.15).
7. O usuário trabalha. Antes de a sessão expirar por inatividade, aparece um aviso com
   "Continuar conectado" (fluxo alternativo A2).
8. O usuário aciona "Sair". A sessão é encerrada e ele volta à tela de login.

### Fluxo alternativo A1: troca obrigatória de senha

1. A tela "Definir nova senha" pede a nova senha e a confirmação.
2. O servidor confere três condições:
   - a senha temporária ainda está dentro das 72 h;
   - a nova senha tem pelo menos **8 caracteres** (PEND-11, DEC-28);
   - a nova senha é diferente da temporária.
3. O servidor grava o novo hash, zera `troca_senha_obrigatoria` e limpa
   `senha_temporaria_expira_em`.
4. O usuário vai para a tela inicial do perfil.
5. Enquanto a troca não acontecer, **qualquer outra rota** leva de volta a esta tela.

### Fluxo alternativo A2: aviso de expiração da sessão

1. **60 s** antes do fim dos **30 minutos** de inatividade (PEND-04, DEC-28), o sistema
   mostra um aviso anunciado por tecnologia assistiva. Isso atende ao mínimo de 20 s de
   antecedência (A11 §5.16.2).
2. "Continuar conectado" renova a sessão. O botão funciona por teclado e por toque.
3. Sem resposta, a sessão expira e a próxima ação leva ao login.

### Fluxo alternativo A3: alterar a própria senha

Vale para qualquer funcionário (matriz de permissões em
[escopo-e-perfis §6](../../docs/escopo-e-perfis.md)).

1. No menu, o usuário aciona **"Alterar senha"** (`/senha/alterar`).
2. A tela pede a senha atual, a nova senha e a confirmação.
3. O servidor confere a senha atual pelo `PasswordEncoder` e aplica as mesmas regras do
   fluxo A1: pelo menos **8 caracteres** e diferente da senha atual (DEC-28, E4).
4. O servidor grava o novo hash, cria uma nova sessão e registra o evento
   `SENHA_ALTERADA` no log, sem a senha.

## Exceções e mensagens

| Situação | Comportamento | Mensagem |
|---|---|---|
| Usuário ou senha incorretos, ou conta inativa | Acesso negado (RF02) | "Usuário ou senha inválidos. Confira os dados e tente novamente." (A11 p.4) |
| Login bloqueado por excesso de tentativas | Acesso negado (RF02) | Ver RF02 |
| Senha temporária vencida (mais de 72 h) | Acesso negado. A tela orienta a procurar a escola | "Sua senha temporária expirou. Procure a escola para receber uma nova." [PROP: texto] |
| Nova senha igual à temporária ou abaixo do tamanho mínimo | Recusa. O foco vai para o campo com erro | "A nova senha precisa ter pelo menos 8 caracteres e ser diferente da senha temporária." (PEND-11, DEC-28) |
| Confirmação diferente da nova senha | Recusa | "A confirmação não é igual à nova senha." |
| Senha atual incorreta (fluxo A3) | Recusa. Conta como tentativa sem sucesso para o bloqueio do RF02 [PROP] | "A senha atual não confere." [PROP: texto] |
| Sessão expirada | Redireciona para o login | "Sua sessão foi encerrada por inatividade. Entre novamente." |

## Dados utilizados

| Dado | Origem | Uso |
|---|---|---|
| `usuario.login` | Banco | Identificação, normalizada |
| `usuario.senha_hash` | Banco | Comparação pelo `PasswordEncoder` (RNF03) |
| `usuario.perfil` | Banco | Define as permissões e a tela inicial (RF03) |
| `usuario.ativo` | Banco | Uma conta inativa não autentica |
| `usuario.troca_senha_obrigatoria`, `senha_temporaria_expira_em` | Banco | Fluxo A1 |
| Sessão HTTP | Servidor | Estado autenticado. Recriada a cada login |
| Evento de auditoria | Log | Data e hora, ação, resultado e login mascarado, **sem senha** |

## Regras de negócio relacionadas

- **RN14:** senha temporária (72 h, troca obrigatória, só hash, temporária com 12 caracteres, nova com pelo menos 8).
- **RN10:** horários gravados em UTC.

## Critérios de aceitação

| ID | Critério |
|---|---|
| CA-RF01-01 | Uma conta ativa, com usuário e senha corretos e sem troca pendente, entra e chega à tela inicial (`/portaria`, a mesma para todos os funcionários, DEC-37) |
| CA-RF01-02 | O login aceita variações de caixa e espaços nas pontas (" ATE.Demo " = "ate.demo") |
| CA-RF01-03 | Uma conta com `ativo = 0` não entra, e a mensagem é a mesma de credencial inválida |
| CA-RF01-04 | Com `troca_senha_obrigatoria = 1`, todas as rotas, exceto `/senha/definir` e `/logout`, levam para "Definir nova senha" |
| CA-RF01-05 | Senha temporária com mais de 72 h não autentica e mostra a orientação de procurar a escola |
| CA-RF01-06 | Depois da troca, o banco tem um hash novo, `troca_senha_obrigatoria = 0` e `senha_temporaria_expira_em = NULL` |
| CA-RF01-07 | A sessão muda de identificador depois do login (proteção contra fixação de sessão) |
| CA-RF01-08 | Depois de "Sair", voltar com o botão do navegador e repetir a ação não acessa a área restrita |
| CA-RF01-09 | O campo de senha aceita colar e tem `autocomplete="current-password"`. A troca usa `autocomplete="new-password"` (A11 §5.9.18) |
| CA-RF01-10 | O aviso de expiração aparece **60 s** antes dos 30 minutos de inatividade (o mínimo de A11 é 20 s), é anunciado sem mover o foco e "Continuar conectado" funciona por teclado (A11 §5.16.2) |
| CA-RF01-11 | A tela de login tem título "Login \| Furin Access", `lang="pt-BR"`, labels associados e foco visível (RNF06) |
| CA-RF01-12 | Nenhuma senha aparece em log, mensagem de erro ou resposta HTTP (A10 §5.17) |
| CA-RF01-13 | Em "Alterar senha", com a senha atual errada, nada muda. Com a senha atual certa e uma nova de 8 caracteres ou mais, o hash muda e a senha antiga deixa de autenticar |
